# 避風塘 Phase 1 設計：劃區、防波堤線、出入口、預覽與存檔

日期：2026-10-03。狀態：已實作（見文末「實作狀態」）。上游：[分階段計劃](typhoon-shelter-phased-plan.md)、[玩法設計](typhoon-shelter-gameplay-design.md)。數值為試玩初值。

## 1. 目標與範圍

玩家劃出一片避風塘水域；系統即時算出它需要的防波堤線、出入口、主航道、泊位估算、保護度和工程費，顯示在地圖上，並隨存檔保存。**Phase 1 只做規劃，不施工、不生船、不收錢。**防波堤真正建出來（用 Phase 0 的 causeway 素材）是 Phase 2。

本設計取代分階段計劃原本的「三種區域」：燈塔／堤頭區不再由玩家另畫，改由水域邊界自動得出；碼頭區留到 Phase 2，由系統在岸線上選址（見 §9）。

## 2. 參考：香港仔避風塘

- 位於香港島與鴨脷洲之間的天然水道。兩邊都是陸地，只在水道兩端用防波堤收窄，留出東、西兩個出入口；分為香港仔西避風塘及南避風塘。
- 北岸是魚市場、公眾碼頭和街渡碼頭；塘內按船隻類別劃分停泊區。例如海事處把入口附近的「A 區」及鴨脷洲大王宮廟西面的「C 區」劃給第 III 類本地船隻。
- 2025 年政府建議向南擴建約 24 公頃（包括通航區）：建兩道新防波堤、設浮式防波堤，改善東面防波堤，並拆除部分西面防波堤。即是**擴建時防波堤跟住新邊界外移，舊堤拆除**。

設計上借用三點：
1. 陸地包圍得越多，越少防波堤，保護越好；最理想是「峽灣式」。
2. 兩個出入口：可以穿塘出入，打風時分流返港，一個入口塞住仍有另一個。
3. 擴建 = 邊界外移、新堤建、舊堤拆。

資料來源：[政府新聞公報：香港仔避風塘擴建工程](https://www.info.gov.hk/gia/general/202506/13/P2025061300376p.htm)、[香港01：擬建兩道新防波堤](https://www.hk01.com/社會新聞/60351924/香港仔避風塘擬建兩道新防波堤擋樺加沙吸巨浪-增設兩遊艇停泊區)、[GAC：西避風塘分區停泊](https://www.gac.com/hot-port-news/enhancement-for-existing-designation-of-berthing-areas-for-different-classes-of-vessels)、[海事處文件](https://www.mardep.gov.hk/filemanager/tc/share/aboutus/pdf/lvac/lvacp5_25c.pdf)。

## 3. 概念與名詞

以下全部以地圖格計，一格 20 m（400 m²，25 格＝1 公頃）。

| 名詞 | 定義 |
|---|---|
| 水域（basin） | 玩家劃定的 WATER 格集合，4 向連通。船停泊和航行的地方，不放防波堤。 |
| 邊界邊（edge） | 水域格與區外格之間的格邊。 |
| 岸線 | 區外一側是陸地的邊界邊（GROUND／HILL／ROAD／DIRT／BEACH）。不需要防波堤。 |
| 開放邊 | 區外一側是水的邊界邊。需要防波堤。 |
| 堤線（ring） | 開放邊外側緊貼水域的一圈水格（含凸角的斜角格），即防波堤將會佔用的格。 |
| 出入口（entrance） | 堤線上留空、不建堤的一段，寬 2 格（40 m，可雙向通行）；所在一邊長過 10 格時可開 3 格。 |
| 堤頭 | 堤線每段的盡頭：堤線轉角、出入口兩側、堤線接岸處。Phase 2 放燈塔／吊機堤頭素材。 |
| 主航道 | 出入口之間（或出入口到岸線）的保留水路，不計泊位。 |

### 為何堤建在水域外圈，而不是水域邊緣

- 水域面積＝可停泊面積，泊位計算不用扣堤。
- 擴建時，舊堤線格變成新水域，新堤線在更外一圈，直接對應「新堤建、舊堤拆」。
- 防波堤直段 30 m、闊約 18 m（含拋石）、堤頭約 16 m（Phase 0 實測）。一格闊的堤線放得下，不會壓到泊位。

## 4. 合法條件

規劃可以畫，但不合法時以紅色顯示並列出原因，不能提交（Phase 2 才有「提交施工」；Phase 1 的提交＝保存為「規劃中」）。

| # | 條件 | 不合法時的提示 |
|---|---|---|
| 1 | 水域全部是 WATER，不含橋、建築、貨櫃碼頭、其他避風塘 | 「水域包含陸地／橋／設施」 |
| 2 | 水域 4 向連通 | 「水域分成幾塊」 |
| 3 | 水域包含一個完整的 6×8 格矩形（任一方向，即 120 × 160 m，約 1.9 公頃） | 「水域最少要 6×8 格」 |
| 4 | 至少一段連續岸線 ≥ 3 格（60 m，日後放碼頭）；斜海岸的樓梯形岸線（格與格斜角相接）亦算連續 | 「要最少一邊靠岸（連續 3 格）」 |
| 5 | 堤線全部是可建的 WATER 格（不含橋、其他水域或堤線、設施） | 「防波堤位置被佔用」 |
| 6 | 水域及堤線離地圖邊至少 1 格 | 「太近地圖邊，建唔到堤」 |
| 7 | 至少 1 個出入口；建議 2 個（只有 1 個時黃色提示，不算錯） | 「冇出入口」／「建議開第二個出入口」 |
| 8 | 出入口位於堤線直段上，兩側各有 ≥ 1 格堤（放堤頭）；寬 2 格，所在一邊長過 10 格時可為 3 格 | 「出入口太近轉角」／「呢邊唔夠 10 格，出入口最闊 2 格」 |
| 9 | 每個出入口外側經水路連到外海（見 §6），不經其他避風塘或橋底 | 「出入口通唔到外海」 |
| 10 | 堤線每個直段 ≥ 2 格（太短的段放不下堤身加堤頭） | 「防波堤有太短的轉折」 |
| 11 | 出入口之間（或出入口到岸線）有主航道 | 「出入口同塘內水路唔通」 |

自動修正：畫區時，只有 1 格寬的凹位或凸位自動填平或削去，避免防波堤出現細碎鋸齒。如此大部分情況下條件 10 自然成立。

最小尺寸 6×8 及出入口闊度上限放在 `typhoon-shelter.js` 的常數（`TYPHOON_SHELTER_MIN_BASIN = { short: 6, long: 8 }`、`TYPHOON_SHELTER_ENTRANCE_WIDTH = 2`、`TYPHOON_SHELTER_WIDE_ENTRANCE = { width: 3, minSide: 11 }`），方便調校。

## 5. 玩家操作

工具放在「土木工程署（CEDD）」分類，只加**一行**「避風塘」，保持選單簡潔。選中後在地圖頂部顯示一條小工具列，切換三種模式：

| 模式 | 操作 |
|---|---|
| 水域（預設） | 拖曳矩形加入水域（同分區工具一樣的 ISO 矩形預覽）。按住 Shift 拖曳則減去。新矩形與現有水域相連時合併為擴建；不相連時開新避風塘。 |
| 出入口 | 在堤線上點擊：開一個 2 格出入口；所在一邊長過 10 格時，再點可加寬至 3 格；右鍵移除。拖曳出入口可沿堤線移動。 |
| 檢視 | 點擊水域或堤線，打開避風塘面板（現有檢視工具點擊同樣可以打開）。 |

**自動建議出入口**：第一次劃出合法水域時，系統自動建議出入口位置。
- 盡量選兩個，位於堤線最遠的兩端（香港仔式穿塘）；只有一條直段時選一個在中段。
- 外側須通外海。
- 玩家可以移動或刪除建議的出入口。

**預覽層**：避風塘工具選中時常駐顯示；其他時候只在檢視時顯示。

| 元素 | 顯示 |
|---|---|
| 水域 | 淺藍填色 |
| 岸線 | 黃色邊 |
| 堤線 | 橙色粗線，每 30 m 一個刻度（將來的堤段） |
| 堤頭 | 白點 |
| 出入口 | 綠色缺口，箭咀指向外海 |
| 主航道 | 白色虛線 |
| 預留避風位 | 斜線網紋 |
| 不合法格 | 紅色，並在面板列出原因 |

拖曳中即時重算（見 §10 效能）。

## 6. 計算

### 6.1 邊界與堤線

1. 由水域格找出所有邊界邊，按區外格分類為岸線或開放邊。
2. 堤線格：每條開放邊外側的那一格。凸角位置另加斜角格，令堤線在角位相連。
3. 堤線格按 4 向相連串成若干條「堤線段」。每段由一連串直段組成，相鄰直段在轉角相接。
4. 堤頭位置：轉角、出入口兩側、堤線接岸的端點。

### 6.2 外海連通

「外海」＝連到地圖邊緣的 WATER 格。由每個出入口的外側格做 BFS，只經過：WATER、不屬任何避風塘水域或堤線、不是橋。能到地圖邊緣即算通。

- 內陸湖、被其他堤圍住的水面都會失敗。
- 橋底一律不可通過（已決定）。日後另行設計「高橋」才可通航。
- 結果按地形版本快取。

### 6.3 主航道

- 有 2 個以上出入口時：塘內 BFS 找出入口之間最短水路。
- 只有 1 個時：找出入口到最近岸線格的水路。
- 航道寬 2 格（3 格出入口亦只保留 2 格航道）。航道格不計泊位，日後也不能放設施。

### 6.4 泊位估算（初值，Phase 3 會再按淨空驗證）

```text
可泊水格 = 水域格 − 航道格
實體泊位 = floor(可泊水格 / 2)        // 一艘 24 m 漁船佔 2×1 格
預留避風位 = ceil(實體泊位 × 預留比例)  // 預設 20%，面板可調 0–40%
日常可用泊位 = 實體泊位 − 預留避風位
```

### 6.5 保護度（0–100，只作預覽；Phase 4 用它計損傷）

可解釋的四項，面板逐項顯示：

```text
岸線包圍 = 40 × 岸線邊數 / 邊界邊總數
堤線完整 = 40 × (1 − 出入口總寬 / 開放邊數)
入口直射 = 20 × (1 − 直射水格 / 水域格)      // 從出入口向塘內直線可見、無陸地或堤遮擋的水格
保護度 = 岸線包圍 + 堤線完整 + 入口直射
```

峽灣式（香港仔）三項都高。四面開放的海中塘只靠堤線，最高約 60。

### 6.6 工程費估算（只顯示，Phase 2 才扣款）

| 項目 | 初值 |
|---|---|
| 防波堤 | $900／格 |
| 堤頭 | $2,500／個 |
| 拆堤（擴建時舊堤線變水域） | $300／格 |
| 每月維護 | 堤線 $15／格 |

參考：貨櫃碼頭 $12,000。一個約 60 格水域、兩個出入口的中型避風塘，工程費約 $20,000–30,000。

## 7. 擴建與縮減

擴建＝在現有水域旁拖曳新矩形。系統重算邊界並比較新舊堤線：

| 格 | 結果 |
|---|---|
| 舊堤線格成為新水域 | 標為「拆堤」 |
| 新堤線格（原本不是堤線） | 標為「新建」 |
| 兩者皆是 | 不變 |

預覽用三種顏色顯示新建（橙）、保留（灰）、拆除（紅虛線），面板顯示淨工程費。這就是香港仔 2025 年擴建方案的做法：南移邊界、建新堤、拆部分舊堤。

**出入口跟隨**：每個出入口記住所在的一邊（n/e/s/w）及沿該邊的位置。
- 邊界外移後，該邊的堤線平移出去，出入口沿同一垂直方向跟出去，保持相同位置與寬度。
- 新位置不合法（例如落在轉角）時，在同一邊找最近的合法位置。
- 再找不到就標為「出入口需要重新指定」，規劃不合法直至玩家處理。

**縮減**：同樣重算。若令水域分裂、岸線不足或出入口消失，該次操作被拒絕並提示原因，不會留下半合法狀態。

**多個避風塘**：兩個避風塘的水域及堤線不可重疊或相鄰；之間至少相隔 1 格水，即外海通道。各自有 ID 和名字。預設名稱為「避風塘 1、2…」，玩家可以改名。

## 9. 與其他系統的關係

- **碼頭**：Phase 1 不劃碼頭區。Phase 2 在岸線上自動選碼頭位置（要接路、供電），並在面板讓玩家指定偏好位置。原分階段計劃的「碼頭區」工具改為可選，暫不做。
- **地形與建設**：水域及堤線格不可放路、橋、建築、貨櫃碼頭、分區。地形工具改動這些格時，規劃即時重算；若變得不合法，在面板及預覽中顯示原因，不自動刪除規劃。
- **貨輪航線**：現有貨輪（`vessel-visuals.js`）的航線可能穿過規劃中的水域。Phase 1 只在面板提示，Phase 2 建堤後才改航線。
- **防波堤素材（給 Phase 2）**：
  - 每條堤線直段按 `layoutTyphoonShelterBreakwater()` 鋪 causeway1 直段。一格 20 m，直段實際 30 m、錯開約 26 m，按段長平均分佈。
  - 轉角及出入口兩側放燈塔／吊機堤頭。只有「尖角向鏡頭」的轉角經目測驗證；其他方向會見到接口。
  - 出入口外側左紅右綠放航標（bout1，IALA A 區入港方向）。

## 10. 資料、存檔與效能

存在 `city.typhoonShelters`：

```js
{
  version: 1,
  nextId: 3,
  shelters: [{
    id: 'ts1',
    name: '香港仔避風塘',
    seed: 918273,                 // Phase 2 自動布局用
    basin: '12:30-41;13:30-41',   // 每行連續段的緊湊編碼 row:c0-c1
    entrances: [{ side: 'w', along: 12, width: 1 }],
    reservePct: 20,
    status: 'planned',            // Phase 2 起：queued / building / operational
  }],
}
```

- 堤線、岸線、航道、泊位、保護度、費用、合法性都是**衍生資料**：不存檔，載入及地形改動後重算。
- `city-state.js` 須加 `typhoonShelters` 的初始化及正規化（新欄位要加入白名單，否則會被清走）。
- 舊存檔沒有此欄位，載入為空。
- 存檔格式版本照現有規則遞增。

效能：
- 重算以單一避風塘為單位，複雜度與水域加堤線格數成正比。
- 拖曳時每幀最多重算一次。
- 外海 BFS 按地形版本快取。地形未變時只重做出入口所在的一段。

## 11. 交付與驗收

**交付**：
- `typhoon-shelter.js`：規劃、邊界、堤線、合法性、航道、泊位、保護度、費用；純函數，可 node 測試。
- 工具及預覽層、避風塘面板、`city.typhoonShelters` 存讀、i18n。

**驗收（單元測試＋遊戲內）**：
- 峽灣、海灣、U 形三個範例的堤線、出入口、泊位、保護度數值符合預期。
- 內陸湖、貼地圖邊、無岸線、出入口在轉角、出入口通不到外海，各自顯示正確原因。
- 擴建：舊堤線正確轉為「拆堤」，出入口跟隨外移；縮減時分裂會被拒絕。
- 存讀後規劃完全還原，衍生資料一致；舊存檔可載。
- 四個地圖方向下預覽位置正確；拖曳大水域（約 400 格）時不掉幀。
- 不改底層 WATER，不影響 RCI 生長及現有貨輪。

## 12. 已決定（2026-10-03）

1. 出入口預設 2 格（亦是最小）；所在一邊長過 10 格時可開 3 格。水域最小 6×8 格。
2. 橋底暫時一律不可通船；日後另行設計「高橋」。
3. 工程費及維護初值照 §6.6。
4. 工具放「土木工程署（CEDD）」，只加一行「避風塘」，模式在地圖頂部小工具列切換。
