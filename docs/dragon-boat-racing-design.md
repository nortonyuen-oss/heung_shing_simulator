# 香城端午龍舟競渡設計

2026-10-11。狀態：首版賽事已實作；以下保留設計目標，實作／驗證範圍見文末。
本文件具體化 `festival-dlc-design.md` §4.2 嘅日間龍舟部分。以下場地尺寸、賽制、數值同動畫時序係遊戲設計；現實資料只喺附有來源嘅段落中描述。

## 1. 香港參考同遊戲方向

- **赤柱：** 主辦協會列出 2026 年端午錦標賽用標準龍、270 米水道，另外亦有 200／250 米賽事。遊戲以 270 米海旁短途賽做主要視覺參考。[赤柱龍舟協會賽事資料](https://www.dragonboat.org.hk/zh)
- **尖東：** 2026 香港國際龍舟邀請賽喺尖沙咀東部海濱舉行，用標準龍、500 米水道。長海岸城市可以做較長嘅邀請賽場景。[中國香港龍舟總會賽事頁](https://hkcdba.org/2026hkidbr)
- **賽事層次：** 邀請賽節目表包括公開、混合、女子等項目，同初賽、複賽、準決賽及決賽。首版香城只做一個城市盃，使用六隊同兩輪排位賽，之後一場決賽；此係配合現有素材嘅遊戲簡化。[官方賽事通告及節目表](https://hkcdba.org/wp-content/uploads/2026/02/2026-HKIDBR_Bulletin_1_TC_Clean_Final.pdf)
- **細節：** 赤柱規則有點睛、登船集結、水道緩衝區、衝線後減速同頒獎；完成時間以龍鼻／最前端過線判定。遊戲採用呢啲可見細節。[赤柱 2026 規則，Part B §1、Part D §5、§7](https://www.dragonboat.org.hk/zh/_files/ugd/b86f40_2faa18dd040949b382fa2c494e41d9bf.pdf)

玩家起海濱步道、揀主會場同籌辦規模，之後觀看城市代表隊比賽。主角係六條船同步起步、互有領先、最後衝線，岸上有看台、裁判台同頒獎。城市每年只辦一個主會場，避免全部海岸都塞滿龍舟。

搶包山沿用總設計嘅夜間規劃，但唔列入今次龍舟實作嘅完成條件；日間賽事應可以獨立交付。

## 2. 場地：岸線同水道分開

沿用至少 **6 格相連海濱步道、面向開放海面** 嘅觀賽場地門檻。步道可以係樓梯形，但相連唔代表一定有合格水道：要另外驗證船隻實際經過嘅直線海面。

遊戲現有尺寸係 1 格 = 20 米。以下長度按地圖座標計，唔按螢幕像素計。

| 項目 | 提案 |
|---|---|
| 常規水道 | 270 米（13.5 格），參考赤柱 |
| 空間較細 | 自動用 200 米（10 格），介面清楚顯示實際距離 |
| 長海岸 | 有空間時可揀 500 米（25 格）邀請賽 |
| 起點後、終點後緩衝 | 各 20 米；每條船全部船身及槳葉都要喺合格水域內 |
| 水道總長需求 | 200 米：240 米／12 格；270 米：310 米／15.5 格；500 米：540 米／27 格；掃描整數格時向上取整 |
| 六條線道 | 每條暫定 8 米闊，共 48 米；呢個係遊戲佈局數值 |
| 海面闊度 | 幾何範圍 80 米；完整格網檢查 5 格／100 米，包含外側返回航道 |
| 比賽方向 | 只用地圖 row／col 軸嘅直線，方便用現有四向龍舟圖 |

**重要：** 6 格係觀賽岸線門檻，唔係 270 米賽道長度。水道可沿同一海灣伸延超出有步道嘅部分；終點同主要看台要位於觀賽岸線附近。海面不足 200 米就記 `noVenue`，唔會將 120 米水面標成 270 米。

第一版選擇算法：

1. 將相連步道分組，枚舉鄰近海面四個軸向、起點位置同兩個競賽方向。
2. 優先試 270 米；冇合格候選再試 200 米。500 米只喺玩家選擇長途邀請賽時啟用。
3. 對六線道、起終點緩衝、登船點、救援／返回路線做完整包絡驗證。全部要係可通航海面，排除陸地、橋、避風塘內水域、船席、碼頭設施同地圖外。
4. 檢查現有渡輪、貨船、遊艇／漁船嘅實際航線及出入通道；唔只檢查碼頭距離。交叉或安全包絡相碰就換位置。
5. 評分：可用場地、步道容量、終點可觀賞程度、附近公共交通、現有公眾碼頭；有公眾碼頭加分，唔係硬性必要條件。
6. 同分用穩定地圖 key 排序。玩家可以喺合格步道 inspect 入面揀「設為龍舟主會場」；無效覆蓋要提示原因。

樓梯形海岸嘅水道係近似平行於海灣主方向嘅直線，唔係逐格沿岸走。第一版唔會改寫運輸公司航線；無法避開現有船路就唔辦。新航線／填海／拆步道令場地失效時，進入中止流程，唔會令船穿過陸地。

## 3. 岸上佈置同素材

| 素材 | 用法 |
|---|---|
| 六色 DragonNW／SW | 首版六隊，每隊固定一色；bake 鏡像補 NE／SE |
| viewersStage | 看台面向水道，放喺終點側或中段寬闊位置 |
| ceremonyStage | 大會／裁判台放喺終點岸邊，唔擋住主要觀看區 |
| championStand1 或 2 | 每年只選一款做頒獎區，唔會兩款並排 |
| pier | 臨時登船浮台，接近集結區、位於競賽線道外 |
| startLine／goalLine | 起終點標記；記錄方向及錨點，唔靠 bounding box 猜位置 |
| guardLine | 水道邊界浮波，分段放置並按材質可讀方向選圖 |
| rescueBoat | 集結時待命，賽事中留喺外側；唔加入競賽排名 |

已校正嘅龍舟及台架見 `scripts/source-art/festivals/DragonBoat/`。浮台、浮波、起終點及救援艇仍要檢查方向、尺寸、透明邊同 bake。

**素材處理規則（Norton，2026-10-11）：** 全部沿用之前等距模型嘅轉換方法及現有 `tools/correct.py`／festival bake 流程：保留 original，按台面／船舷／浮標中心連線等結構取點，先垂直 skew 平衡左右角度，再調整 Y/X 至地面軸斜率 ±0.5，保留垂直線。單一方向或圓形物件用已有單軸／橢圓參照方式，唔生造第二條量度線。處理後裁透明邊、等比縮放、底部置中補 POT 畫布，唔將物件直接拉成畫布比例。

方向唔合放置位置時，用 **水平鏡像反轉** 補另一側視角，再按地圖旋轉揀圖；唔用任意旋轉 PNG 取代等距方向。龍舟 NW ↔ NE、SW ↔ SE；看台、大會台、頒獎台、浮台、浮標繩及起終點標記同樣按岸線／朝向選原圖或鏡像。鏡像喺 bake 時生成，沿用既有 `_m` 材質規則。同步鏡像地面／水線／龍鼻／尾端／量度點等 anchor（連續座標 x → width − x；像素索引 x → width − 1 − x），實際米數保持一致。

如果鏡像後仍缺少所需正反面，唔用縮放／旋轉硬扮該視角，要記錄缺圖。含可讀文字嘅素材拆開處理：結構可以鏡像，文字另行保持正向；唔令隊名或贊助字樣倒轉。

每個岸上物件按佔地放置，保留步道至少 3 米通道。步道位置太窄時將看台減量或移到相連岸上空地；大會台同頒獎區仍需有可用空位。唔將整座看台壓喺窄邊上，亦唔重疊碼頭入口。

### 3.1 全部素材按 1 格＝20 米量度（Norton，2026-10-11）

龍舟、浮標、浮台、救援艇、看台、大會台、頒獎台、旗幟同人物全部跟同一地面比例。校正後嘅 power-of-two 畫布只供材質儲存，透明留白唔屬於物件尺寸。

每件素材建立量度記錄：實際長／闊／高（m）、原圖結構取點、校正版及 bake 後對應取點、地面／水線 anchor、遊戲 render scale、放置後量得嘅米數及佔格數。未確定嘅尺寸明確標為試玩初值，唔以 PNG 畫布闊度當船長或台面闊度。

地面投影按現有 100×50 格：沿 row／col 嘅 20 米位移，螢幕位移分別係 (−50,25)／(50,25) px（zoom 1）。所以沿地圖軸嘅每米係水平 2.5 px、垂直 1.25 px；斜邊實際像素長度約 2.795 px/m。唔將「2.5 px/m」誤當斜邊 Euclidean 長度。高度沿既有 renderer 嘅 5 px/m 計，唔攞人物高度反推地面長度。

正式放置時加 20 米格網及 1 米子網格，用物件兩端／四角驗證：18 米龍舟船身應為地圖軸一格長度嘅 0.9；水花同翹起嘅頭尾唔計入水線長度。所有方向及 0／90／180／270 度地圖旋轉都要量度；鏡像圖換 anchor 後唔可以換咗實際尺寸。

浮標按單粒直徑先定 scale，再量繩段間距；台架按台面長闊，而唔係高旗幟；救援艇按水線；浮台按甲板佔地。需要更長繩段就拼接／調整繩本身，唔將浮標、人物或龍頭一齊拉大。

每類至少留一張城市格網截圖及量度表先算完成。現階段只有校正版原圖，尚未放入城市，所以唔宣稱已完成遊戲內尺寸驗收。

一般觀眾／工作人員素材尚缺：唔借用六四持燭人群或 UFO 目擊者。Norton 已於本輪指定人群先唔加入；本版保留空看台，唔以人群作驗收條件。點睛暫用靠岸龍舟、大會旗同短文字提示；未有點睛角色素材之前，唔聲稱有完整點睛人物動畫。

## 4. 六隊城市盃同賽制

首版賽名「香城龍舟邀請賽」，獎項仍稱城市盃。以下六隊由 Norton 於 2026-10-11 指定，取代之前四區加商會／漁民隊嘅提案：

| 隊色 | 隊名 | 名稱來源 |
|---|---|---|
| 紅 | `{districtName}街坊福利會` | 遊戲內任一真實區域名稱 |
| 綠 | 香城女神隊 | 固定使用有女性鼓手嘅 greenDragonNW／SW |
| 藍 | 李彩樺漁業聯會 | 固定名稱 |
| 黃 | 漁民樂海鮮酒家 | 固定名稱 |
| 黑 | 香城討論區毒L | 固定名稱，保留大寫 L |
| 紫 | `{transportCompanyName}小輪職工會` | 遊戲內運輸公司名稱；冇公司則用城市名稱 |

只有綠色係指定配色；其餘顏色按上表作首版預設。隊名、顏色、線道同排名同時顯示，唔單靠顏色辨認。女性鼓手唔代表全船都係女性，唔將「女神隊」誤報為女子組賽事。

`districtName` 優先從城市區牌選一個已存在名稱，冇區牌亦可從 `getBaseCityDistricts()` 嘅既有區域中以固定 seed 選擇，使用 `getDistrictNameForTile()` 嘅名稱規則；唔自行生一個不存在嘅區。保留玩家名稱原文，唔強行刪「區」或改字。

運輸公司名稱取 `getTransportExpansionState().company.name`；公司未成立（`foundedYear === 0`）或名稱空白時，改用 `city.name`，再空白先用「香城」。例如「太子小輪職工會」。唔要求城市先有渡輪航線先准呢隊參賽，亦唔去掉公司名稱既有後綴。

當屆開始時將區域／公司／隊名配色寫入快照；改區名／公司名會於下屆生效，已公布賽果保持原名。其餘五支非區域隊用城市平均人口／快樂度作封頂實力參照，唔冒認佢哋屬於某個區。

**提案賽制：兩輪排位賽 → 六隊決賽 → 頒獎。** 六隊都入決賽，介面稱「排位賽」，唔聲稱有淘汰。首版先將同場競渡做好，擴展更多隊伍時先加入分組初賽／複賽。

- 每輪排位分數由第一至第六為 6 至 1 分；兩輪加總。
- 同分按兩輪總時間，再按第二輪時間，再按穩定 team id 排序。
- 排位較高嘅隊依次排入 3、4、2、5、1、6 線道；第二輪亦輪換線道。
- 決賽全部由同一條起點線出發。排位成績唔帶入起跑距離，六線道第一版冇額外速度加成。
- 城市盃冠亞季軍由決賽衝線時間決定；極罕見內部時間完全相同就按排位排序。顯示時間至少兩位小數，避免畫面先到而結果後到。

每隊實力以訓練底值、地區人口嘅封頂影響、快樂度同每年／每場固定 seed 產生嘅狀態決定。人口影響要封頂，細區亦有機會贏；政府規模只影響佈置、人流同效果，唔直接令某一隊更快。

每場先產生固定完成時間，再用連續、單調向前嘅分段速度曲線畫位置：起步加速 → 中段維持 → 最後衝刺。曲線可以有超前同追近，但唔會倒後、超出線道或喺終點瞬移。

## 6. 船隻動作同視角

- 六船同時起步，各自有少量上下浮動同局部浪花強弱變化；唔旋轉成隨便角度。
- 現有圖已包含槳手同水花，係靜態姿勢。首版用整船微動營造節奏，唔假裝已有逐槳動畫；水花額外效果限少量 sprite／alpha 變化。
- 記錄每個視角嘅 **船身中心、龍鼻、尾端及水線**。原圖下方有水花，素材 bottom-centre 唔等於船身位置；競賽需要獨立 anchor，避免六船對線唔齊。
- 同一艘船各方向按相同實際船身長度縮放，唔按包含水花嘅整張圖闊度計。首版暫定船身 18 米，正式 bake 前用中心線量度；此係遊戲素材尺寸，唔宣稱係香港標準龍規格。
- 轉地圖時只重新投影同換圖；位置、線道、進度同結果都唔變。
- 衝線以龍鼻 anchor 判定，唔用船中心；過線後向前減速至緩衝區，再沿外側返回。
- 返回路線逐段揀四向圖；無法喺合格海面建立返回路線嘅候選要淘汰，唔會直接穿過其餘線道返岸。
- 「去睇」固定對準終點與主要看台嘅中景。玩家可點擊單船睇隊名、線道、當場排名／成績；唔自動追住領先船來回 pan。

## 7. 天氣同中止

赤柱規則係早上 06:00 如有三號或以上風球、紅／黑雨，延期至 10:00；天氣未改善就取消。本遊戲嘅龍舟亦採用較嚴格嘅水上賽事判斷，作為總設計一般戶外活動規則嘅特例。[赤柱規則 Part B §9](https://www.dragonboat.org.hk/zh/_files/ugd/b86f40_2faa18dd040949b382fa2c494e41d9bf.pdf)

- 06:00 有三號或以上／紅黑雨：記錄 `delayed`；唔派船。
- 10:00 仍不適合：取消日間賽事；若已改善，縮減成一輪排位賽加決賽。
- 比賽中遇到上述天氣：中止該場、撤回可通航等候區；未完成決賽唔頒冠軍。首版中止後當日唔重賽，避免天氣短時間來回變化反覆派船。
- 黃雨：比賽可繼續，觀眾提案減 40%；純小雨唔自動取消。
- 08:00 後場地被拆／填海／新航線侵入水道：按場地失效中止；危險 sprite 立即移除，其餘清場。
- 日間龍舟取消唔自動決定夜間搶包山；夜間節目日後獨立判斷場地同天氣。

呢啲係遊戲事件狀態，唔以人物受傷、死亡或隨機翻船做首版內容。

## 8. 財政、效果同城市生活

沿用簡辦／標準／盛大倍率 0.5／1／1.6。標準規模籌辦費提案為 `$1,800 + 人口 × 0.015`，全屆只收一次；此為試玩數值。

| 規模 | 岸上佈置 | 比賽 |
|---|---|---|
| 簡辦 | 1 座看台、1 座大會台、1 頒獎區 | 同樣六隊，兩輪排位＋決賽 |
| 標準 | 2 座看台、更多旗幟及觀眾 | 同上 |
| 盛大 | 有空間先加至 3 座看台、人流更密 | 同上；唔用加速船隻表達規模 |

資金不足唔出船，記 `skipped`。冇合格場地記 `noVenue`，唔收費。天氣取消退未使用嘅營運部分，提案為費用嘅 50%；已完成一輪後中止退 25%，其他已花費部分保留。此係遊戲財政提案，唔引用真實賽事退款規則。

決賽完成：標準旅遊 +3、吸引力 +3、快樂 +0.015，持續一個月，沿用既有節日效果倍率。效果喺確定完成後先加入，避免取消咗仍收到完整獎勵。

總設計嘅步道兩格內商業收入 +10% 要新增局部收入計算支援；列為後續工作，唔用全城 `commercialDemand` 代替。首版唔新增參賽費或博彩。薩利亞係指定遊戲內贊助商，加入廣告文案；暫無指定贊助金額，唔自動增加財政收入。

比賽開場、決賽同頒獎各有一次短提示；跑馬燈播決賽／冠軍消息。論壇一篇年度賽事帖，完成後記冠軍及名次；取消就寫取消原因。正文只使用引擎已確定嘅隊伍、結果、場地同天氣。

新聞稿、爆冷／險勝變體、延期／取消／中止分支及圖片使用規則見 [香城討論區龍舟新聞稿](dragon-boat-forum-news.md)。每屆只發一篇終局主帖；開賽同延期先用短通知，避免現有 `addForumPost` 去重邏輯令舊開賽帖阻擋賽果稿。

## 9. 存檔同現有框架接法

位置由 clock + seed 計算；唔儲每幀 sprite。**天氣延誤、取消同已公布嘅賽果係不可從目前天氣重新推算嘅事實，必須儲存。**

提案新增 `city.festivals.dragonBoat` 當屆紀錄：年份／月份、穩定 seed、規模、場地及 course 快照、六隊身份／配色／實力、各場完成時間、延誤／中止狀態、已結算費用／退款／效果／消息旗標。所有欄位經 `normalizeFestivalState` 白名單及長度限制。年度 history 擴充摘要：冠軍、前三名、距離、場地、退款及取消原因；history 上限仍為 40。

- `festival-venues.js`：收集可通航水域／運輸航線 context，新增純函數選水道同岸上 slot。現有 DFS 步道走訪只可用嚟分組，唔可直接當船隻路線。
- `festival-assets.js` + bake：註冊 12 船、4 台架及浮台／標記／救援艇；補鏡像同 anchor metadata，保留 POT 畫布。
- `festival-dragon-boat.js`（新增）：當屆快照、排位分數、完成時間、船隻姿態、天氣事件及結算。唔將動畫塞入 `simulation.js` 主迴圈。
- `festival-sprites.js`：靜態台架沿用原 renderer；移動船隻加入動態 placement 同 depth／mask／culling。clock 進度用畫面更新計算，場地掃描只喺地圖／航線變動時重算，唔每幀掃全海面。
- `festivals.js`：加入日間節目同經濟定義；現有月初 `settleFestivalMonth` 會即時加完整效果，端午需改成付費同完成效果分開，避免退款／效果重複。
- `festival-ui.js`：顯示主會場、距離、六隊、排位／決賽、上屆冠軍；校正工具加場地包絡預覽同各階段預覽。

暫停、讀檔、改速度、跳月份都唔重收費、退款、加效果或寫重複論壇。跨過決賽窗口時根據中間事件紀錄完成結算，唔因冇畫出某幀就漏結果。已中止當屆唔會因讀檔後天晴復活。關閉節慶會移除 sprite／材質並處理當屆中止，唔再次退款。

## 10. 實作次序同驗收

1. **場地先行：** 以太子等真實存檔選候選水道，畫出六線道、起終點、船身包絡及返回線；驗證樓梯岸、各方向、橋／船路排除同最小場地。
2. **六船競渡：** 素材註冊、浮標／起終點端點處理、四向圖、全部素材 20 米格網量度、統一船長／龍鼻 anchor、六隊指定隊名與配色、三段速度、過線減速、返回同旋轉地圖。
3. **完整日間節目：** 排位兩輪、決賽、看台／大會台／頒獎、一般觀眾素材、通知及成績牌。
4. **可靠結算：** 當屆存檔、天氣延誤／取消、場地失效、資金、退款、效果及論壇。
5. **整體驗收：** 日間各階段截圖；1x／8x／暫停／讀檔；六船衝線名次同畫面一致；同一 seed 得同一結果；低人口區有取勝可能。

性能沿用總設計：新增節日高峰 FPS 跌幅 ≤10%，全場 sprite 預算約 150 件、共用 worldMask、按需載入及完整卸載。以非節日及端午高峰相同鏡頭／天氣／時間量度；唔以海面空曠場景代表密集城市表現。

實作嘅第一個可檢查交付物係 **真實存檔上海濱外嘅六線道＋六艘船對齊起點**，然後先加入賽事劇情同經濟。

## 整條水道與完整流程預覽

產物：`.data/dragon-boat-review/index.html`（可跳章節／調慢速度）、`course-overview.png`、`full-process.mp4` 及 `measurement.json`。錄影用遊戲 renderer，06:00 至 18:00 以正常遊戲 2 倍速度約兩分鐘呈現，包含準備、兩輪排位、決賽、頒獎時段及清場。頒獎時段顯示台架及賽果，冇人物動畫。

270 米競渡嘅 nominal 水面範圍為 310 × 80 米；實際逐格驗證因 half-tile 對齊及比賽方向，可能為 16–17 × 5 格。呢次固定向西嘅完整展示係 17 × 5 格（340 × 100 米，85 格）。岸上至少六格相連步道另計；觀賽岸線唔要求覆蓋全段水道。

返回流程已改為外線先離開，逐隊相隔 0.6 顯示分鐘，沿外側航道返回。返程先喺起點前方 20 米轉入自己線道，再倒向對線位置，避免跨過已停喺起點嘅其他船。救援艇移到返回線外側 7 米，保持航道暢通；轉向以船身中心做連續定位，唔因鏡像改 heading 而跳位。

重建：先以隔離 profile 執行 `scripts/drive-electron.js scripts/preview-dragon-boat-course.js`，再將輸出 WebM 轉為 MP4，最後 `node scripts/build-dragon-boat-review.js`。展示腳本會清理測試地形嘅樹木及碎屑，並檢查水面樹木 0、結束後賽事 sprite 0、終結新聞稿 1。

## 競渡動作第二版（2026-10-11）

參考已觀看取樣畫面嘅 [2025 沙田龍舟實拍](https://commons.wikimedia.org/wiki/File:Dragon_boat_races_in_Sha_Tin_(20250531113609).webm)（HingWahStreet，CC BY 4.0），並閱讀 [2026 赤柱偏航撞船片段報道](https://hk.on.cc/cnt/news/20260620/bkn-20260620163009923-0620_00822_001.html)。實拍呈現隊伍拉開距離；赤柱報道描述撞船尾後偏航，再遭鄰船接觸。未將片段角度當成速度或事故機率量度；下列參數係遊戲調校。

修正相近隊伍編號喺舊 FNV 隨機函數產生過於接近數值嘅問題。新賽事使用打散後嘅種子，分別抽取實力、當日狀態、起步反應、扒船節奏、體力下降、後段衝刺同操舵能力。每 0.25 秒模擬一次前進同横向位置；渲染同賽果共用同一條航跡，唔再只按預先完成時間作直線插值。

日常會有約 1–2 米橫向搖擺；部分場次有鄰線偏航。只有兩艘未完成船嘅船身重疊（縱向距離最多 17 米、橫向最多 2.8 米）先記錄接觸，推開兩船並減速 4–8 秒，同時終止失誤操舵再返回原線。領先船已離開事故位置就唔會被劇情強行撞中。橫向位置限制喺 -3 至 43 米，保留既有水道空間。撞擊有短暫水圈提示，討論區只會描述實際已發生接觸，唔加傷亡情節。船圖保留原有四個等距方向及鏡像，唔旋轉 bitmap 破壞投影。

新存檔用 `motionVersion: 2`；位置樣本不寫入 JSON，由年度種子及隊伍快照重新生成。未有版本欄位但已包含賽果嘅舊存檔走第一版算法，保留既有名次及完成時間，唔重抽已公布結果。

驗證新增速度差距／偶發接觸、船身真實重疊及減速、航跡邊界與衝線連續、兩版本讀檔、碰撞新聞去重測試。全套 910 個測試通過。新版預覽另附 `final-race.mp4` 決賽四倍慢播，方便觀察拉開差距及偏航相碰。
