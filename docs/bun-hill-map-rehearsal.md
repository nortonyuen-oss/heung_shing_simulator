# 海旁搶包山場地測試

在 test mode →「啟動 event」選擇「啟動海旁搶包山測試」或「預覽搶包山個人決賽」。這是地圖上的實際素材場景；原有「預覽搶包山選手動畫」仍是獨立示意塔面板。

需要岸上的活動空地：標準 4×3 格（80×60m），不足則找最小 3×2 格（60×40m）。每格必須已建、同高度且無其他建築完整 footprint／水面佔用。外側至少三格相連海濱步道，至少兩個獨立邊緣入口，同高度且面海；不使用公共碼頭或橋旁。四個朝向皆可，廣場和步道分開計算。

`scripts/prepare-bun-hill-assets.py` 保留原圖，依接地角點校正左右斜率至 ±0.5，預乘 alpha 重採樣，再打包 1024×1024 畫布及鏡像。幾何、錨點、來源角點與米制尺寸存於 `data/bun-hill-geometry.json`。

2026-10-11 比例修正：上一版強行把包身定為 14m，結果欄杆放大到約 3m，與人不成比例。現在按原圖欄杆接地／頂部的垂直距離，把三款塔的欄杆定為約 1.1m；選手仍為 1.7m。

戲棚第二次校正：舊控制點用了不同高度的梯腳，不能當作同一水平矩形。改為量度同一層屋簷竹樑的三個轉角，先 skew，再調整 Y/X，使兩個主軸都為 ±0.5；其投影到支柱底部的矩形決定錨點及米制佔地，並另外預留梯級空間。原始圖保持不變；輸出仍為 1024×1024 及鏡像版本。曲面花牌、旗幟及斜屋頂本身不視為水平校準線。

2026-10-11 最新布局按使用者手繪圖整理，取代早前左側戲棚與分散觀眾方案。局部 Y=0 是靠海的後沿，Y 增加走向前沿觀眾；戲棚居後沿中央，主塔位於中央偏後，兩座展示副塔位於左右偏前。前沿分成左、中、右三群，海濱通行帶、左右出口及前方 6m 通道保持開放。花牌現在掛在兩邊欄杆上，各三塊，戲棚缺口保持。

小場也保留兩座副塔，以已量度的 10×10m／10×8m 預留區放置，沒有縮細模型。小場主塔禁入區調為 16×12m，包含 8×8m 主塔預留區；大小場的副塔及觀眾均不進入主塔禁入區。

左右各一段折角欄杆，從戲棚兩側沿後沿延伸，再轉向前方，在副塔之前結束；中央戲棚缺口及前方保持開放。欄杆每約 2m 一柱，高 1.1m，使用原生 graphics 依實際地面等距投影繪製，分段排序以避免旋轉時整條欄杆蓋住前方建築。跟隨搭建至拆台階段，收檔清空，結束測試銷毀。

觀眾沿用龍舟四款前／後視角與鏡像素材，直接使用 `data/festival-textures.json` 的已烘焙錨點及頭腳距，不使用尚未烘焙的原圖控制點。身高維持 1.7m；每組預留 5×4m，每列組中心相距 6m、前後列相距 4m，標準場每群五組（3+2）、小場每群四組（2+2），三群都面向戲棚／包山方向。搭建及拆台時不顯示觀眾。

目前戲棚沿用原有正面及左右鏡像的兩個素材視角；地圖四向旋轉會保持地面定位，但沒有新製作背面棚牆視角。

腰部／落地錨點與素材 release 裁切縮放保持一致。選手沿錐形包身上攀、摘包、下降；安全繩接到腰部安全帶，塔後選手被包山遮擋。地圖轉向後更新鏡像、人物朝向、位置及深度。

決賽固定 12 人（9 男、3 女），三座塔各四人（3 男 1 女），每塔混合高／中／低取包策略。選手不會複製；每人的固定 towerIndex 隨重播保持一致，各塔按自身實測高度、錨點、半徑及深度計算攀爬與遮擋，每塔各有前後安全繩圖層。固定 seed 決定事件，拖動和重播不重新抽結果。3 分鐘前落地才有有效成績，截止後逾時選手仍會安全下降；分數、包數及失格結果不再改動。成績表可在測試控制列展開。

播放 1× 用 180 秒完成決賽，3× 用 60 秒。節目時間軸從 18:00 搭台至 02:00 收檔；接力時段目前只顯示待接入，沒有以個人賽動畫假冒接力。三群前沿觀眾已接入，尺度與選手一致。

測試暫停城市模擬，天空顯示隨測試游標轉到夜晚；不修改城市儲存的時間、年月、資金、比分歷史或新聞。結束、退出 test mode、換城或場地被拆除時會清理 sprites、安全繩及自用 GPU 材質，恢復模擬速度及原時鐘顯示。正式節日流程已接入端午月夜間排程、自動選址、費用及退款、天氣／場地取消、完成效果和賽果新聞。接力與活動音效仍待實作。

驗證：`test/bun-hill-event.test.js` 檢查海岸幾何、洞及坡度、碼頭／橋旁、四向配置、素材比例、時鐘隔離及截止後返回。`scripts/preview-bun-hill-event.js` 只在獨立 Electron profile 建立實際步道與 12 格空地，檢查 0／20／70／170／180 秒、四向鏡像與對位、播放及清理。截圖及量度在 `.data/bun-hill-design/map-event-*`。

這批包山美術本身是矮而闊的展示塔。放大整張圖無法同時得到 14m 塔身及成人腰部高度的欄杆；本版優先保留欄杆／人物比例，沒有再把塔身硬定為 14m。比賽原型的 14m 策略高度只作正規化進度，在地圖重映射至實測塔高並預留 1.7m 的頭部空間。三張塔圖也不是滿包／半空／空塔；可移除平安包圖層仍待製作。

2026-10-11 花牌修正：參考 [政府檔案處「1990年的長洲太平清醮」照片集](https://www.grs.gov.hk/ws/erp/Cheung-Chau/sc/home/index.html) 中的包山對開攤檔照片（HKRS2021-1-2_A004）：大型花牌與包山、竹棚框架結合。這是遊戲布局的參考，不代表所有醮場都必須照同一位置搭建。現有 bunHillSignboard 是沒有門洞的完整花牌，不能當成可穿過的牌樓。先移除了放在空地中央的獨立花牌；後續依使用者要求，改掛於欄杆上，並非可穿過的入口。

布局的單一 `gate` 已改為 `signboards` 座標陣列，支援零塊或多塊；目前標準／小型各六塊，每塊記錄 point、side 及可選 axis。標準場全部沿後側横欄分兩組；小場每邊兩塊沿後欄、一塊沿折角側欄。地圖渲染、平面圖及 Electron 檢查同步使用新的配置；最新位置以本文件前面的使用者草圖布局為準。日後設置多塊時，應先確定棚架／邊界的實際位置及通道，不能只因有素材就放在場中央；它們不計作場地入口。實際入口仍由海濱步道與活動空地的相鄰格決定，兩個以上出口的要求保持。

欄杆花牌的底部錨點上移 1.1m，牌面保留原有 6m 尺度及 2:1 校準，不再放在場中央；左右各三塊，未使用門洞模型。觀眾兩列的完整 5×4m 組 footprint 都在各自區域內，小場副塔稍向後移以騰出觀眾區，但仍在主塔之前。

觀眾站位修正：三區仍各五組／四組，人物維持 1.7m。改用固定種子的左右與縱深錯位，標準場中區改為前二後三，兩側前三後二，消除三區相同方陣；前後排也有整體橫向偏移。每區交替使用兩款人物素材，左、中、右分別望向左塔、主塔、右塔。觀眾區稍加深／加寬供錯位使用，完整 5×4m 組佔地仍不重疊、不進通道或塔身預留；播放與旋轉不重新抽站位。其他戲棚、花牌、欄杆、塔及比賽配置保持。

正式流程：節慶年曆新增獨立「海旁搶包山之夜」開關及撥款，沿用遊戲既定端午月夜間節目，不依賴龍舟有否成功舉辦。18:00 搭台、19:00 開放，23:30 通知、00:00 三塔個人賽、00:15 結算、00:35 頒獎、01:00 拆台、02:00 收檔。日間仍可繼續城市模擬；正式模式不暫停或覆寫城市時鐘，不顯示測試播放控制。

`city.festivals.bunHill` 保存屆次、單調環境分鐘的 sky-day base、場地快照、seed、撥款、支出、退款及開場／賽果／效果旗標。使用 `environmentMinutes - base` 跨午夜；正常月份在 06:00 才更換，因此 00:01 讀檔還原同一屆。場地快照的 tiles/exits 由合法 row/col/方向重新計算，不接受存檔任意注入的格列表。賽事仍由固定 seed 重建事件，動畫和賽果共用同一結果。

搭台時收取 `1200 + population × 0.008`，乘現有基本／標準／盛大倍率；無場地或資金不足不收費，未有場地可在開賽前重試，錯過午夜不追收或補辦。開賽前取消退 50%，開賽後退 25%；只有完成才給一次吸引力 +1、旅遊 +1、快樂 +0.005（乘撥款倍率），並記錄節日歷史。重複 update、午夜及賽果後讀檔不再扣款、不再發布或派效果。

紅／黑雨、三號及以上風球、地面缺格／地勢改變、步道入口／連通失效、关闭開關或撥款「唔辦」會取消未完成活動。手動跳月／跨 sky-day 會中止未完成屆次，不能虛構冠軍。香城討論區會在完成時發布三塔比賽及得獎者、失格名單，取消／未能舉辦時發布原因與費用，不使用龍舟撞船圖片。

`test/bun-hill-live.test.js` 驗證跨午夜、存檔正規化、一次結算、前後退款、沒有場地／補建、錯過開場、資金不足及跳月。`scripts/preview-bun-hill-live.js` 在獨立 Electron profile 用真正的 compact save 序列化與載入流程，於午夜及頒獎後讀檔，再檢查一次收費、一次新聞／效果及 02:00 收檔。正式賽事截圖為 `.data/bun-hill-design/live-event-race.png`。
