## 節目定位

延續遊戲既定的「日間龍舟、夜晚包山」，放在端午所在月，同一片海旁可以先後舉辦，但分開選址、判定、記錄及收檔。日間龍舟找水道；夜間搶包山找岸上的平坦廣場。龍舟取消／沒有水道，不代表夜間活動取消；夜間没有廣場，也不影響已完成的龍舟賽。

現實長洲搶包山屬太平清醮。2026 年開幕禮於晚上 23:30 開始，個人決賽午夜開始，之後有接力邀請賽；遊戲把它放在端午月是原有世界設定。[政府活動公告](https://www.info.gov.hk/gia/general/202605/18/P2026051800289.htm)

## 場地條件：岸上廣場

所有數字為遊戲場地設計，並非香港活動場地規例。1 格 = 20 米；空間包含包山、戲棚、觀眾、通道及工作區，不能只驗證包山底座。

| 項目 | 日間龍舟 | 夜間搶包山 |
|---|---|---|
| 核心位置 | 海旁對開水面 | 海濱步道旁陸地 |
| 幾何條件 | 200／270 米直線水道、緩衝及回程 | 連續平坦矩形廣場，岸線可彎曲 |
| 標準場地 | 水面另計，270 米賽道通常預留約 320 × 100 米 | 4 × 3 格 = 80 × 60 米 |
| 最小場地 | 沿用龍舟選址器 | 3 × 2 格 = 60 × 40 米，一座競賽包山 |
| 海旁連接 | 至少六格相連步道，且水道合格 | 至少三格相連步道，廣場入口直接接到該步道 |
| 海面 | 必須足夠且不受航線阻擋 | 不要求航道、深水或長直線海岸 |
| 觀眾方向 | 朝海面、集中岸邊 | 朝包山、站在指定觀眾區 |
| 碼頭／橋樑 | 避開航道及通行衝突 | 不佔碼頭、橋頭或其通道 |

第一版選址使用海濱步道內側、由 `event_ground` 活動空地拼成的完整同高度矩形。每格 20×20 米、暗紅磚地連接、石磚只圍外邊；6 格為最小場地，12 格為標準場地。海濱步道在廣場外側，不能算入這 6／12 格，也不能把未鋪地草地自動當成合格場地。步道岸線可彎曲，不要求龍舟的直線水道；只須實際入口連接至少三格相連步道，兩側出口有公共通路。其他建築、公園整體、道路或水面不能被算成活動空地。所有實體擺設均落在廣場內，海旁原有行人線保持通行。

米制數據記錄在 `data/bun-hill-geometry.json`，來源接地點及 affine 係數可重建。主塔包身（不計旗桿）14 米、zoom 1 高 70 px；選手 1.7 米、高 8.5 px。三款原圖支撐連圍欄接地邊長分別約 14.93×14.78、18.40×16.32、19.33×16.60 米，加腳座邊距後預留 18×18、22×20、22×20 米，不能沿用早期未量度的 8×8 米。戲棚正面 12 米，另量得深度 5.16 米，預留 14×8 米；牌樓跨度 6 米，预留 8×4 米。現實曾使用約 14 米高、直徑約 3 米的競賽包山，但這批遊戲美術的塔身及支架較粗，保留其外形，按實際佔地擴大場地。[政府包山及計分介紹](https://www.info.gov.hk/gia/general/201305/15/P201305150261.htm)

## 自動選址與場地提示

1. 列出相連至少三格的步道區段，對每個海側方向枚舉岸上廣場；逐格驗證地圖範圍、陸地、同一地形高度及活動空地紀錄。用 `findEventGroundRectangle()` 檢查真正 3×2／4×3 矩形，不補洞。
2. 檢查建築完整 footprint（僅活動空地自身允許）、道路、橋頭、碼頭、樹木、路牌及現有節日保留區。不能只查建築 anchor，不能偷偷拆建築、移树或填海。
3. 對每個候選布局再檢查物件的實體 footprint，以及原有路燈、長椅、欄杆位置。門及通道與相連步道接通，場內觀眾到兩個出口有可通行路徑。
4. 玩家指定的場地合格就優先；自動模式先找標準場地，才試最小布局。同級優先日間龍舟附近，其次較少障礙及較短步道連接，最後以穩定座標 ID 決勝。
5. 開始搭台後固定該場地。玩家在場內興建、改地形或拆入口時重新驗證；未開賽可重新選場，開賽後中止並公布原因，不瞬移包山。

選址結果提供 `footprintTiles`、`widthM`、`depthM`、`seaDir`、`entrances`、`reservedPolygons`、`rejections`。失敗提示例：「搶包山需要至少 3 × 2 格平坦海旁空地；此處有 3 格受到阻擋」。候選受阻格數只作提示，不能把最接近合格的場地直接當合格場地。

三分鐘是競賽內時間，計分事件落在 0–180 比賽秒；畫面顯示獨立倒數。城市天空時間的 00:00–00:15 映射到這 180 秒，不把 00:15 誤寫成真實比賽歷時十五分鐘。現有 `GAME_DAY_NIGHT_CYCLE_REAL_MS = 8 * 60 * 1000`，1× 一個天空日只需八分鐘，三個遊戲分鐘只對應一秒實時，因此一般模式的十五個遊戲分鐘也只有五秒實時。

另提供「觀看完整賽事」：暫停城市時鐘，以獨立的回放游標在 60 秒實時中播放同一場 180 比賽秒（可切原速 180 秒），在回放畫面清楚顯示比賽內倒數與回放速度。回放只讀已固定的事件時間線，不自行寫城市結果、費用或新聞；離開後回到原城市時間、鏡頭及暫停／速度狀態，再由正常時鐘結算。此觀看模式需另行實作，並非現有慢速按鈕已足夠。

## 比賽規則及動作

12 名選手，初版 9 男 3 女。低／中／高區包數各以 1／3／9 分計；男女分組選最高有效分數，「代代平安獎」取所有有效選手中包數最多者。總分同分時以預先記錄的選拔速度排名決勝。現實參賽者須在時限前返回地面，逾時成績取消；這項規則也在遊戲畫面顯示。[康文署 2026 參賽者須知](https://www.lcsd.gov.hk/en/bun/common/pdf/bsc_ntp_tc.pdf)

每位選手有攀爬速度、搶包效率、體力及回程估計能力，從城市／年份／選手 ID 的固定 seed 產生。可見策略包括快攀高分區、穩守中層、搶低分包數；領先高度不等於領先分數。越後期手部動作及攀爬速度可減慢。少數選手判斷回程太遲，最後顯示 DQ，不捏造受傷事故。

動畫狀態為 `waiting → climbing → collecting → descending → grounded`；每人有固定攀爬扇區、安全繩及塔面深度。塔前選手畫在塔前，塔後選手被塔身遮蔽；不能把人體当飄浮 sprite 沿屏幕 y 軸滑上去。搶包動作減少對應區域的可見包數或使用透明缺包 mask；三張不同款包山不互換成「滿包／半空／空塔」動畫。

接力採遊戲版三隊、每隊三棒：每棒取指定包並落地後交接，以全隊完成時間排名。參考康文署三人一組、摘指定包後返回地面的接力邀請賽，但遊戲縮減隊數；官方 2026 年邀請名額為十隊。[康文署節目表](https://www.lcsd.gov.hk/tc/bun/schedule.html)

原型個人賽有高分區／中層／包數三類策略，各人上攀速度、取包節奏、疲勞及回程預留不同。一次取包對應一次事件；畫面包數及積分從同一批事件推算。固定範例包含逾時選手，DQ 的原始摘包分數只作裁判展示，不參與任何獎項。回放不重新抽籤；年份或城市 seed 改變才生成另一場。原型已測試午夜階段、重播一致、分數與事件一致、有效返回及同分排序。

戲棚燈、包山射燈採 scene 燈光／透明光束，不直接把 UFO 誘拐光柱當正式節日燈具。包山屬陸上固定結構，不套龍舟浮沉。塔燈反映在近岸水面，建築及人群仍沿用夜間 tint。遠距離減少繩索及小手部動畫細節，但比分不變。

## 聲音、論壇及天氣

戲棚音樂獨立循環一個 channel，開幕鑼及倒數只播一次；距離、zoom、音量及暫停沿用現有環境彩蛋音效。原有遊戲背景音樂維持 30% 輸出。不要同時循環另一首龍舟音樂；18:00 先確認日間聲道已停，再進夜間聲道。音源需玩家提供或使用已授權素材，沒有專用音源就先留可接入的 key，勿把划槳聲搬到包山。

香城討論區：入夜預告一帖，頒獎後一帖，若天氣或場地造成中止則一帖交代原因。例：「【午夜爭包】{選手}奪{城市}包山王，{選手}封后」；正文公布有效分數、包數、接力及 DQ 原因。沒有搶包山新聞圖時不套龍舟撞船圖。第一版不另外承諾薩利亞贊助此活動，沿用日間贊助只在龍舟新聞中出現。

夜間天氣規則獨立於日間結果：開賽前遇三號或以上風球、紅／黑雨取消；比賽中警告升級則選手返回、停止計分、中止而不頒新冠軍。雷暴如有現成可靠狀態才接入。遊戲没有選拔賽實際成績時，不以虛構預賽名次頒冠軍。

## 午夜存檔及實作接口

現有 `game-clock.js` 的單調環境分鐘以正常 06:00 開日；每逢 1440 環境分鐘進入下一個月。午夜只有顯示鐘由 23:59 回到 00:00，正常仍是同一個月。不能以 `minute >= 18*60` 作唯一活動條件，否則午夜主賽會被清除。若測試工具或舊存檔的兩個時鐘沒有對齊，也不能把午夜誤作新屆重新收費。

增加獨立 `city.festivals.bunHill`，以搭台时的年月為所属届次，儲存 `eventId`、場地快照、選手、計分事件、比賽版本、實際完成／取消狀態、费用、已發帖 ID、效果旗標；另存相對 `environmentMinutes` 的 `setupAt/raceAt/closeAt`。正常天空日起點 `base = floor(environmentMinutes/1440)*1440`：18:00 搭台是 `base+720`，午夜开赛是 `base+1080`，02:00 清場是 `base+1200`，以這些單調時間判定階段。不能直接把顯示鐘分鐘加在 base 上。載入 00:01 還原同一場；06:00 換月前已清場。若玩家手動跳月，未完成的活動明確中止，不生成下一屆冠軍。

為避快轉漏結果，以單調環境時間處理每個已越過且未處理的搶包／返回／公布節點。結果和动画共用事件時間線；畫面快轉可少畫幀，但結算不漏。重複 update 或讀檔不再收費、不再派效果、不再發帖。

接口拆成純函式 `selectBunHillVenue`、`validateBunHillLayout`、`bunHillPhase`、`simulateBunHillContest`、`bunHillPose`，以及場景更新／載圖／清場。復用現有材質加载、等距定位、音效距离控制和論壇 API，禁止在尚未收檔时自动换场。

費用建議初版 `baseCost 1200 + population × 0.008`，沿用基本／標準／盛大倍率；没有收入款项。没有場地不收費；開賽前取消退 50%，開賽後中止退 25%。完成才給一次旅遊 +1、吸引力 +1、快樂 +0.005，與龍舟分開記錄。這些都是待實作的遊戲平衡值。

Test mode 的「啟動 event」增加「啟動搶包山之夜」（18:00）及「預覽午夜搶包」（23:58），先檢查場地再跳時間，重複測試不扣錢。使用原始場地检查条件，不为了展示在水面上搭塔。

## 驗收

- 四個海側方向與四種地圖旋轉；2:1、鏡像 anchor、20m/格及人物尺度一致。
- 岸線曲折但陸上廣場合格可辦；水面寬但岸上狹窄不可辦；碼頭、橋、道路、建築及不平地不能被覆盖。
- 跨 23:59→00:00 及讀取 00:01，活動及届次不變；06:00 的 12 月→1 月已清場；快速跳過整場時結果／退款／效果／帖子各一次。
- 個人賽分數與可見摘包一致；同分、最多包數、男女組、逾時返回 DQ 及最小場地略過接力可重現。
- 人群留通道，從兩側散場；塔後選手正確遮擋；夜間音樂只有一條，收檔釋放圖像、音效及保留區。

實作次序：先加入候選廣場與格網預覽 → 素材校準及夜間静態場景 → 午夜回捲生命周期 → 選手動畫與同一時間線計分 → 音樂／論壇／測試入口 → 太子有合格廣場後錄製完整節目。
