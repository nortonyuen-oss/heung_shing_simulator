# Phase 4：跨區路網、交通時間與區域聚合

分支：`codex/world-chunk-streaming`。世界預覽新增可操作的巴士／列車來回班次，以及人口和財政聚合。依照 [規格第 7 節及 Phase 4](world-chunk-streaming-spec-v1.0.md)，路網、班次、人口、時鐘及預算都由世界資料持有，與九個詳細 Render Chunks 的生命週期分開。

## 操作

沿用 `npm start` 及 `/world/preview.html`，靜態預覽可使用 IndexedDB。新舊世界載入後，未曾啟動的模擬保持暫停，不會自行扣除維護費。

1. 鋪設相連道路或地面路軌；道路可以經橋樑連接兩岸。
2. 從建設工具選「巴士班次起終點」或「列車班次起終點」，依次點選路網上的起點與終點，預覽路徑後按「新增班次」。
3. 左下「世界運作」按「開始模擬」。可切換 1／4／16 倍速、暫停，或按「前進一日」。一個模擬日為 60 秒世界時間；班次在該時鐘上往返。
4. 班次選單的「查看」會跳到車輛目前位置，「移除」只取消班次，保留道路／路軌。
5. 道路旁劃住宅，並在相連道路旁劃商業／工業或興建公共街市，才會有可容納人口及可達職位。左下顯示世界人口、住宅容量、職位及上日收支；右上預算扣除建設費與日常淨支出。

手機預設收起世界運作面板，點標題展開；附近小地圖及全港總覽繼續保留。只有瀏覽權的分頁會停用模擬操作並說明另一分頁正在寫入。

## 路網與交通

`WorldTransportNetwork` 從已建設的稀疏道路、橋樑及鐵軌建立兩套世界 Tile 索引。查詢不需要 Render Chunk、Sprite 或讀取 Base Terrain。

- 道路以四鄰接連通，最多容許一級高度差；橋樑只在兩端接入陸路，不能從橋中段橫向上橋。
- 鐵路只連接相同高度的相鄰路軌。道路與鐵路分開，不會在平面重疊附近誤接。
- 最短路徑跨過 32／64 邊界，不把 Chunk 邊界當作路線終點。每次查詢最多訪問 100,000 個已建節點，班次路徑上限 8,192 格、班次上限 64。
- Connected component ID 使用該組最小世界 Tile 編號，不受建造順序或存檔區塊排序影響。
- 只有道路／橋樑／鐵路變動或載入存檔才重建路網。劃分區、財政及每秒時鐘更新不重建路網。
- 路線中斷時，班次保留 ID、端點及累計完成程數，標為中斷並停止移動；修復後重新尋路，再由起點出發。路徑改變亦重新起程。

每個班次初版提供一個來回交通物件，端點停靠兩秒。示意行駛時間為道路每格 2.5 秒、鐵路每格 1.25 秒，與世界速度倍率一致。班次進度採路徑距離與時間計算，離開鏡頭時不生成逐格動畫，也不停止計時。

`WorldTrafficRenderer` 只為詳細範圍內的班次建立顯示物件；離開後真正銷毀，返回時按當下進度插值。四方向投影、高度及深度排序沿用世界 Adapter。小地圖額外顯示淡色班次路線與位置點，交通時間變動只重畫輕量鏡頭／位置層。

## 區域聚合與初版規則

`WorldSimulation` 在建設資料改變時，重新建立最多 1,900 個 Storage Chunk 的稀疏統計；不掃描 7,648,800 個原始 Tile，也不逐格逐幀執行舊單城模擬。

住宅與職位按相連道路 component 分配。相同路網內的可達職位可服務其他區域的住宅，並按住宅容量比例分配人口目標，避免每個 Chunk 重複使用全網同一批職位。

這一版採明確的基礎平衡值，尚未搬入舊城市的完整需求／解鎖規則：

| 項目 | 每格／每棟基準 |
|---|---|
| 住宅容量 | 每級密度 8 人 |
| 商業／工業職位 | 每級密度 6／10 個 |
| 公共街市職位 | 24 個，需道路接入 |
| 人口目標 | 不超過住宅容量及可達職位的兩倍 |
| 每日遷入／遷出 | 向目標移動，步幅為容量／現有人口的 1/20 向上取整，至少 4 人 |
| 每日稅收 | 每人 $2 |
| 每日道路維護 | 每格 $1 |
| 每日橋樑／鐵路維護 | 每格 $2 |
| 每日街市／公園維護 | 每棟 $20／$30 |

資金最低為零，未支付維護額累計顯示。按完整模擬日結算，因此同一段時間分多次推進，與一次長時間補算的最終人口、預算及帳目一致，包括途中資金耗盡。

人口穩定前只做有限次區域成長計算；穩定後將餘下日期一次合併結算。路線進度亦直接計算完成程數及循環餘數，沒有把離線日數或離線行程逐個排入 queue。時鐘倒退不重算已經過的時間。

## 存檔與一致性

世界 schema 仍為 2，增加有獨立版本的可選 `simulation` 欄位（version 1）。其中保存世界時間、牆鐘時間、暫停／倍率、各區人口、累計收支、班次端點、路徑、進度及完成程數。舊 Phase 2／3 存檔沒有此欄位，仍可載入，首次操作模擬時才建立。

模擬時鐘和預算由同一個 metadata transaction 發布及保存。沒有修改的 Storage Chunks 不會標 Dirty。獨立 `constructionRevision` 讓每秒時鐘不會令建設預覽失效或令既有建築重新掛載；確認建設時仍重新驗證可用資金。

模擬變動每 15 秒觸發受控儲存，連續 tick 不會無限延後儲存；建設沿用較短的 1.2 秒 debounce。儲存中的新模擬修改仍然 Dirty，未成功寫入不會清除。SQLite／IndexedDB 原有交易、版本衝突、上一版、完整匯出／匯入保護繼續適用。

若保存時正在運行，下次載入以保存時的時鐘補算經過時間；暫停存檔不補算。唯讀分頁不更新或保存模擬。世界匯出包括畫面外班次及人口，仍採 20 MiB 檔案上限。

亦修正了原有匯入結果沒有回傳 snapshot 的遺漏，讓 UI 正確恢復視角、記住新 slot，重開頁面後仍使用該份匯入世界。

## 驗證

```sh
npm run test:world
npm run smoke:world:simulation
npm run smoke:world
npm run smoke:world:construction
npm run smoke:world:navigation
npm test
```

新單元測試覆蓋跨區道路／長橋／鐵路連通、高度隔離、橋中段誤接、班次插值及保存、拆路／修路、時鐘倒退、暫停／倍率／離線、唯讀分頁、跨區就業、長時間與逐日收支等價、建設草稿不受時鐘影響、SQLite 失敗回退、儲存中的新 tick、損壞模擬資料、持續 tick 的定期儲存、匯入回傳資料與路網 ID 穩定。

`smoke:world:simulation` 使用獨立 Chromium context 及臨時 SQLite，分別走 IndexedDB／SQLite 真實流程：在地形上整地、跨 64 邊界鋪路／鐵路、滑鼠選兩端建立班次、變速／暫停／推進日期、遠區繼續行駛與收支、卸載後零交通顯示物件、保存／重載／返回、拆路停駛、修路恢復、四旋轉、完整匯出／移除／匯入新 slot、重載離線補算及唯讀第二分頁。另有手機觸控操作。報告及截圖在 `test-results/world-simulation/`。

本次完整套件 **1,349 項通過**，世界專項 **46 項通過**，串流、建設、導航及模擬四組 Chromium smoke 全部通過。兩種後端均保留 48 人、兩個交通班次，遠區及離線補算後仍可返回；詳細區塊掛載峰值九塊，沒有 JavaScript page error。原有未提交修改與真實城市 fixture 的內容雜湊亦保持一致。

## 後續界線

這是世界交通與聚合的第一版。仍未搬入正式單城的巴士站／地鐵站、乘客排隊、班次密度、擠塞、電力／服務覆蓋、生長建築模型、船舶／飛機及完整需求平衡；本階段的交通物件是示意車輛。舊城市模擬繼續使用原有引擎。

Phase 5 接長時間與大量已建路網壓力測試、Safari／Electron／實體手機驗收、幀時間與保存延遲量測、主選單及發佈資產整合。此次 Chromium 的功能驗證不能代替上述平台與發佈驗收。
