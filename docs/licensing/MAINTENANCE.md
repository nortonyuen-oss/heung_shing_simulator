# 長期授權維護與發行

## 現況與後續維護

- 根目錄 `LICENSE` 為 v1.0 正式文本；`THIRD_PARTY_NOTICES.md` 記錄第三方來源與限制。公開署名為 `nortonyuen-oss`，聯絡入口為 GitHub Issues。
- 官網 `copyright.html` 提供四種語言摘要，`LICENSE.txt` 與 `THIRD_PARTY_NOTICES.txt` 是根目錄原文的逐位元組副本。修改原文後執行 `npm run sync:legal`，發布前執行 `npm run check:legal` 檢查同步狀態；現有 GitHub Pages 流程會隨 `docs/**` 更新部署。
- `package.json` 與 lockfile 根項目的授權為 `SEE LICENSE IN LICENSE`。自訂專有條款不標成 MIT 或其他開源識別碼。
- 本次只發布授權與網站資訊，沒有重建或重發既有安裝包。下次桌面版須另外驗證玩家可離線讀取正式條款及全部第三方原文；`docs/**` 目前被打包規則排除。
- 繼續確認 Suno 音樂、Google Earth 海岸線、天文台年曆、地景與錄音的使用範圍。修改本專案的授權不能清除上游限制。
- 舊版網站及安裝包已有的有效許可繼續按其範圍處理；不把新條款追溯套用到已發行版本。

## 每次新增依賴或資源

- 優先使用有明確商用／散布許可的來源；MIT／ISC／BSD／Apache 等仍保留原文與各自必要條件。
- GPL／AGPL／LGPL、CC BY-SA、限制非商業或禁止改作的內容，需先按使用方式評估；不能只靠單一允許／禁止清單判定。
- AI 素材記錄服務、生成日期、輸入參考與操作者；Suno 另記官方下載資格及證明。
- 新增資源時補登 ASSET-RIGHTS，導出 WebP、夜景、縮圖、圖示時記錄母檔，權利限制隨衍生檔保留。
- 不明來源不得標示為自有；若決定替換，連 repository 新發行內容、網站截圖與實際安裝包一起檢查。

## 可重跑的盤點

```sh
node scripts/audit-licenses.js
node scripts/audit-licenses.js --check
```

腳本讀取 lockfile、Git 追蹤的媒體／資料與本機 npm 套件文件；不下載套件、不修改權利判定、不連線。

它產生套件與資源清單、雜湊和正式 npm 依賴的通知工作底稿。`--check` 只確認產物與當前檔案吻合；**通過不代表授權合規**。本機沒安裝的套件、缺原文或版本不符，都明列於輸出。人工來源登記與判斷維持在 Markdown，不會被重新掃描覆蓋。

## 每個正式發行包的驗收

- 先確認內部 package.json 為本次版本。舊的 release 目錄不能作新版本證據。
- 檢查 macOS arm64／x64、Windows 安裝版與免安裝版的實際 `app.asar`、`app.asar.unpacked`、外部 Resources、安裝器及其他執行庫；核對實際元件清單與版本。
- 確認 sharp／libvips 沒有意外帶入；若有，排除或完成其散布義務，不能只依賴 devDependencies 標記。
- 確認 Electron／Chromium 通知與精確執行環境版本一致；補 npm 與 CDN／vendored 元件的完整通知。
- 未核准素材若被移出該版本，應確實不在包內。默認靜音、隱藏選單或移除程式引用不等於停止散布檔案。
- 安裝後離線開啟條款與第三方通知；確認網站／About 可找到同一版內容。
- 封存版本、套件／素材清單、雜湊與授權快照；證明檔有私密個資時存私人檔案庫。

## 社群貢獻與委外

保留商業權利與接納貢獻可以並存，但每份貢獻的授權要清楚。不要把開 Issue、提 PR 或 DCO 簽署自動視為獨占權利轉讓或無限制重新授權。

接受程式、美術、翻譯或音樂前，以適當的貢獻協議／委外合約記錄：

- 貢獻者有權提供的範圍、僱主或共同作者是否有權利、第三方及 AI 來源清單。
- 權利轉讓或非專屬授權的選擇；若要支援未來閉源發行、移植、商用及重新授權，必須明確涵蓋修改、重製、散布、公開傳輸、再授權與必要地域／期限。
- 署名、報酬、原始工程交付及已接受版本授權是否持續有效；不得概括要求放棄依法不可放棄的權利。
- 玩家影片及直播的用途是否也被允許；音樂需區分錄音、詞曲、演出和必要的影音結合權利。

不要用一段 README 宣告假裝既有貢獻者已同意新合約；先盤點貢獻歷史，再取得真正的同意。
